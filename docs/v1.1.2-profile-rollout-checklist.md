# v1.1.2 profile rollout: integration checklist

Status: **NOT READY FOR CUSTOMER APK TEST**. DeviceLocalProfilesFeature.ENABLED remains false.

## Required account behavior

- Family account: Main and family-created profiles are remote-backed and follow the same login on all devices; personal viewing state follows each family profile.
- Shared customer account: Main controls addons, plugins, catalog and row layout. Up to five personal profiles per device stay private to that device. Personal history, progress, watchlist and profile metadata must never be uploaded under the shared account.
- Never decide mode from profile name or profile ID. Resolve from verified authenticated account identity. Missing or changed identity defaults to legacy cloud behavior.

## Blocking integration work

1. Persist the verified account-mode assignment keyed by stable authenticated account ID; clear/ignore stale assignment on logout/account switch. Wire AccountProfileModeResolver into the actual authentication lifecycle.
2. Replace global DeviceLocalProfilesFeature.ENABLED checks in sync services and stores with a per-account resolved mode. Family mode must preserve all legacy sync paths.
3. Implement a non-destructive customer migration transaction: back up existing local profiles and state, map colliding secondary IDs without losing viewing data, persist completion, and avoid remote profile deletion.
4. Ensure shared Main layout and plugin/addon configuration are refreshed on secondary profiles without importing Main's personal viewing state. Test cross-device changes while a secondary is active.
5. Audit and test all upload, download, realtime and background sync paths (including Trakt, collections, provider credentials, watch history, progress, PIN, and profile settings). Customer personal state must never reach the shared account.
6. Run unit and instrumentation tests plus signed install-over upgrade verification on production v1.1.1. Test family and customer accounts separately and verify logout/account switching.
7. Only after checks pass, produce an isolated beta APK for user testing. Do not publish to production store or change v1.1.1.

## Safety controls already added

AccountProfilePolicy, AccountProfileModeCodec, AccountProfileModeResolver, AccountProfileTransitionPolicy, DeviceProfileMigrationPlanner and CustomerProfileMigrationGate provide testable policy/preflight boundaries. These are **not yet wired to login and migration execution**. A passing Android build does not prove privacy isolation.
