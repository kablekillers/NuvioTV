# TV 1.1.2: personal viewing-state sync audit (incomplete)

Status: **NOT READY FOR CUSTOMER APK TEST**. `DeviceLocalProfilesFeature.ENABLED` remains false; this document is not a deployment or migration approval.

## Identified asynchronous account/mode hazard

Both `WatchProgressSyncService` and `WatchedItemsSyncService` resolve `canSync(profileId)` from the current per-account mode when their public functions begin. Their network operations can suspend; the original account or profile mode can change before a remote result is applied or a local mutation is acknowledged.

The initial permission check **is not** proof that the same authenticated account still owns a network response. Do not enable device-local customer profiles until each personal-data sync path carries and revalidates a stable verified account identity, mode, and profile ID through every suspension and before any resulting local mutation. The same guard is required for outgoing requests immediately before sending, plus background/realtime callbacks.

## Concrete paths requiring verification

| Area | Code | Required proof |
|---|---|---|
| Watch progress | `core/sync/WatchProgressSyncService.kt` | No secondary-profile push/delete after mode switch; no stale account pull merged into new account; no stale mutation acknowledgment |
| Watched items | `core/sync/WatchedItemsSyncService.kt` | Same safeguards for snapshots, deltas, single/batch writes and deletes |
| Library / collections | `core/sync/LibrarySyncService.kt`, `CollectionSyncService.kt` | Personal watchlist, favorites, and private collections are not pushed under a shared account |
| Profile metadata | `core/sync/ProfileSyncService.kt`, `ProfileSettingsSyncService.kt` | Customer Main remains remote-backed; secondaries stay local; family profiles retain legacy cloud behavior |
| Credentials/settings | `core/sync/ProviderCredentialSyncService.kt`, tracking/Trakt paths | No secondary-profile credentials or private settings sent to shared account |
| Startup/realtime | `core/sync/StartupSyncService.kt` and subscribers | No queued or delayed sync using an old account/mode snapshot |

## Blocking requirements before activation

1. Identify every public/background/realtime entry point and every mutation or RPC side effect for these services.
2. Capture verified account identity and resolved profile mode when work starts; recheck before remote dispatch and again before applying data or acknowledging outgoing mutations.
3. Cancel or discard stale work on logout/account switch. No cross-account pull may overwrite local personal state; no post-switch push may transmit it.
4. Ensure all existing sync jobs are stopped before migration; the DataStore factory barrier alone does not quiesce network operations.
5. Add account-switch and mode-switch tests that suspend between request and response, including cancellation and retry cases, for family and shared customer accounts.
6. Run upgrade and multi-device privacy tests before the feature flag is enabled.

The `ProfileSyncIdentityFence` is wired into RPC/JWT-refresh wrappers in `WatchProgressSyncService` and `WatchedItemsSyncService`, and the outgoing watch-state batch upload paths now retain an additional identity snapshot across delete and upsert requests. New tests cover account switches during a response and between batch operations. **This is not full sync isolation:** inbound snapshot/delta operations retain an original-account snapshot and recheck before local merge and cursor writes. Watched-items paginated snapshots also check that each page belongs to the same session, and new regression tests cover account switches during tracking-provider preflight before network dispatch. These are **not yet** full suspended-response and cross-account merge integration tests; checks are not atomic with concurrent logout. All other acknowledgment and metadata boundaries, account-switch cancellation, and other sync services still require review and tests. An identity check is not sufficient to atomically coordinate account changes across all side effects. Customer mode remains disabled.

This audit is intentionally fail-closed and remains **incomplete**. It is not evidence that other sync services are safe.
